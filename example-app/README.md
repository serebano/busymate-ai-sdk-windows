# Windows example app (WPF)

`Busymate.AI.Example.Wpf` is a WPF app that consumes `src/Busymate.AI`, the actual SDK from this repository, through `BusymateChatView`. On Windows with the .NET 8 SDK and the WebView2 Runtime: `dotnet run --project example-app/Busymate.AI.Example.Wpf`. CI also publishes it (framework-dependent, win-x64) as the `busymate-ai-example-wpf-win-x64` build artifact; run `Busymate.AI.Example.exe` from it.

The default route `https://busymate.ai/support/busyproxy?channel=desktop&locale=en` is the real hosted guest chat. Your own tenant's chat URL and assistant slug can be configured in Settings. The left panel holds settings and a bounded callbacks log; the chat fills the rest of the window.

Settings: assistant, HTTPS chat URL, locale (rewrites the `locale` query parameter), exact origins, **Guest** (no identity bridge) or **Identity** (bridge plus your authenticated-backend mint URL, account ID and optional session bearer), native microphone adapter on/off, an optional native consent dialog after the tap, close/ready handlers, and navigation restriction. **Apply** validates and recreates the WebView. Other buttons: sign in / sign out and account-state refresh, reload, open Windows microphone privacy settings, reset to guest defaults. Values live only in process memory and are never persisted or logged. The bearer is your own backend session credential, never a Busymate service key. Setting an account ID does not authenticate you: your real backend must authenticate the session, mint a fresh nonce-bound assertion and return `{token, nonce}`. The demo makes a real HTTPS POST with the SDK mint fields and refuses redirects; it does not fake a successful identity.

The log shows lifecycle, actions, media decisions and process-failure recovery without JWTs, nonces, account IDs or audio. A `close` action hides the chat and offers **Reopen chat**. Microphone permission is requested by tapping the real hosted microphone/voice controls; Retry, denial, grant and cancellation happen in the hosted chat. The SDK never opens Settings itself; the settings button does, on your click. With the adapter off, the example denies media requests rather than showing the WebView2 prompt. There is no fake crash button; to exercise recovery, end the `msedgewebview2.exe` processes in Task Manager.

History, knowledge retrieval, tools, human handoff, themes, locale and voice availability are hosted tenant capabilities configured in the Busymate workspace. The public busyproxy route does not prove every tenant service is enabled.

Unit tests (`tests/Busymate.AI.Tests`) compile this app's `DemoSettings.cs` and `BackendMint.cs` and check settings boundaries, the defaults, callback toggles, nonce matching, status mapping and redirect refusal. Live WebView2 behavior, Windows privacy and real microphones need the checklist in [`../docs/microphone.md`](../docs/microphone.md).
