# Identity and authentication

Use the v2 `BusymateBridge` (wire 2, build 2.0.0). Windows has no legacy v1 bridge. Install exactly one identity bridge per `CoreWebView2`, before the first navigation: `BusymateChat.AttachAsync` and the helper controls do this for you; on your own `CoreWebView2` call `await BusymateBridge.InstallAsync(core, config)` before `Navigate`.

Your authenticated backend mints a fresh single-use launch assertion for each SDK mint callback. Never cache or reuse a token/nonce pair. Never put a signing key, Busymate admin key or service-role credential in the app. Use your existing authenticated HTTPS backend API. The callback returns `BusymateBridge.MintResult.Success(token, nonce)`, `MintResult.NotSignedIn` or `MintResult.Failed`; preserve the nonce the chat requested and bind assistant, audience and origin server-side. The request dictionary carries the chat's fields (today `nonce`, `aud`, `reason`) plus `assistant` and `origin`, which the bridge sets itself from its configuration and from WebView2's report of the posting document; a page can never choose them. A signed-out app returns no identity. Do not invent a public Busymate mint endpoint for your app: implement your tenant's authenticated backend endpoint using the official [identity guide](https://busymate.ai/docs/guides/mobile-in-app-support).

`Account` is a synchronous delegate reading your current account ID or null. Its hash, SHA-256(`appId:accountId`) truncated to 128 bits, identifies account changes; the raw ID is not sent. `appId` defaults to the entry assembly name; set `Config.AppId` to keep it stable across renames. Call `AccountChanged()` (on the installation or on `BusymateChat`) after login, logout or account switching; v2 emits a `state` event and hosted chat owns identity refresh and clearing behavior. Configure `OnClose` to dismiss your host and `OnAction` only for a fixed app-owned set of actions, returning whether handled. Do not expose arbitrary native execution.

The bridge cancels the mint callback's `CancellationToken` and answers `timeout` after 15 seconds. That ceiling only reclaims the callback; the chat owns every real budget.

Keep navigation restricted to your trusted chat URLs. `BusymateChatOptions.RestrictNavigation` (default on) cancels top-level navigation to any origin outside the identity, microphone and navigation allow-lists and opens user-clicked https links in the system browser; new windows are never opened inside the app. The `open` operation opens https URLs only, in the system browser by default (`Config.OpenUrl` overrides it). Identity availability failures keep chat anonymous (`not_signed_in`, `mint_failed`, `timeout`, `unsupported`); never log token, nonce, raw account ID or audio while troubleshooting.

The byte-frozen [v2 wire contract](../CONTRACT-v2.md) defines hello/state/mint/open/action, error envelopes, version negotiation and events. Its no-new-permissions statement applies to the identity bridge alone. Optional microphone integration explicitly adds microphone use.

The example authenticated-backend client refuses redirects to prevent forwarding the app session credential. Configure the final HTTPS mint endpoint directly. The example's sign-in/out buttons change the native account reader; your own app authentication and backend session logout remain your responsibility.
